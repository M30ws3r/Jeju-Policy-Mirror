## 1-1. 외부 공개 데이터 (보조 점검)

| 이름 | 유형 | 출처 | 기간 | 활용 항목 | 이용 조건 |
|---|---|---|---|---|---|
| 카드 관광 읍면동 리 월별 통계 | 파일(CSV) | 제주관광공사 제주관광빅데이터플랫폼 (원천 BC카드) | 2022.12 ~ 2025.07 (사용 구간) | 기준연월, 관광객 구분(도민·내국인 관광객·외국인 관광객), 읍면동, 카드 매출액, 이용건수 | 공공누리 제1유형(출처 표시), 회원 로그인 후 유의사항 동의하고 다운로드 |

- 원본 73만 977행(약 39MB)을 월×이용자 구분×읍면동으로 합산해 4,128행 집계본으로 저장했다(`card_emd_monthly_202212_202507.csv`).
- 제공처 유의사항: 법인 소비·현금·업종 구분이 안 되는 전자상거래는 제외, 온라인 결제는 본사 소재지로 잡히거나 누락될 수 있음, 조회 시점에 따라 값이 달라질 수 있음. 유의사항에는 '도민 소비 제외'라는 문구도 있으나 실제 파일에는 '도민' 구분이 들어 있다(제공처 확인 필요).
- 쓰임: 시행 후 12개월간 도민과 내국인 관광객의 카드 소비 변화(전년 같은 달 대비)를 비교해, 차이가 3%p 를 넘으면 '지역 소비 수요 변화' 주의를 붙인다. 읍면동–노선 연결은 아직 하지 않았다.
- 재현 방법: 플랫폼 > 데이터 픽 > 소비 > '소비 건 당 매출 분포' > CSV 다운로드(기간 2022-12 ~ 2025-07) → 월·관광객구분·읍면동별 합계.

## 3. 수집

- 버스: `scripts/fetch_bus_skip.ps1` (또는 `fetch_bus.ps1`). 조건 `moveType=승차, priceType=일반, payType=카드`.
  - 하루치가 조건 적용 시 약 600건(6~7회 호출)이라 전량 수집 불가 → 분석 기간(2022.12 ~ 2025.07)을 **4일 간격으로 먼저 수집**하고 남는 쿼터로 사이를 채운다. 요일이 고르게 섞이고, 중간에 멈춰도 전 기간이 균등하게 확보된다.
  - 날짜별 파일(`data/real/bus_days/YYYYMMDD.csv`)로 저장, 이미 받은 날짜는 건너뜀. 허브에 자료가 없는 날은 빈 파일로 기록.
  - 저장 시 세부 경로별 합계만 남긴다(노선명, 이용자 수). 개인 단위 정보는 원천에도 없다.
- 카드: 950건 전량, 10회 호출.
- API 키: 실행 시 입력받고 파일에 저장하지 않음. 제출물에 포함하지 않음.

## 4. 전처리·분석 흐름 (버스)

1. `scripts/build_bus_monthly.py`: 세부 경로(예: `325-15`)를 노선번호(`325`)로 합산 → 노선×월로 **평일 하루 평균, 주말 하루 평균**을 따로 산출. 빈 날은 평균에서 제외, 자료가 있는 날에 기록이 없는 노선은 0명.
2. `pipeline_bus.load_panel`: 표본일 3일 미만인 달 제외, 평일·주말을 5:2 로 가중한 하루 평균.
3. 비교 후보: 사례표의 조정 노선을 뺀 뒤, 전 기간 매달 이용 기록이 있는 노선.
4. 대상(노선 묶음은 합산)과 비교 노선 평균의 로그 격차 → 이중차분, 점검, 등급.
5. 출력: 노선 단위 집계만 저장·표시.

## 5. 합성 샘플 (자유 질문 시연)

`backend/app/agent/sample.py` 가 고정 시드 난수로 12개 지역 × 48개월 카드 소비를 만든다. 지명은 예시이고 수치는 실제와 무관하다.

## 6. 반출·제출

- `data/real/` 은 `.gitignore` 로 저장소에서 제외한다. 제출 ZIP 에 집계본(`bus_monthly.csv`)을 넣을지는 센터 반출 조건 확인 후 결정한다.
- 결과물(JSON·PDF)에는 노선 단위 집계와 통계량만 있다.

## 7. 개인정보

분석 데이터는 모두 집계 통계이며 개인 식별 정보가 없다. 서비스가 저장하는 개인정보는 (로그인 사용 시) 이메일뿐이며 AES-256-GCM 으로 암호화한다. 센터 모드(`AUTH_REQUIRED=false`)에서는 계정을 만들지 않는다.
